The package is installed by Composer into a separate consumer directory as a copied dependency, then loaded only through that consumer's `vendor/autoload.php`; the smoke rejects a source-only/autoload-only substitute. The parent checks exact remaining owner IDs after each release, then zero owners at both RR and RC. All process, database-readiness, Docker, and cleanup waits are bounded.

This smoke uses a focused `wpdb` bootstrap from released WordPress core. It does not exercise a full WordPress admin request, plugin activation, production admissions barrier, external writes, or a published registry install. The [E5-01 runbook](../../migration.md) and earlier full native suite cover distinct requirements; a successful local smoke cannot replace exact-head remote candidate CI, B5 merge, or independent E5-QA.
