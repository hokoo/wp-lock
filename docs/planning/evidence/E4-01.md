# E4-01 lease-time implementation boundary

**State:** implementation and directed six-row verification accepted by root; full-suite/coverage, independent epic QA, and B3 delivery remain pending. E4-01 is `review`, not completed.

The backend already starts finite TTL from a fresh primary-database time read after the permanent resource row is locked and checks remaining TTL with another database-time read after COMMIT. E4-01 adds an expiry check when `release()` acts on a confirmed owner. That check uses the exact attempt token and a fresh primary-database time after the resource lock; an observed expired owner raises `WP_Lock_Ownership_Lost` and clears the wrapper's held handle. A confirmed missing or replaced owner retains the same loss result, while an uncertain release whose exact row is absent retains its existing reconciliation behavior. Exact-token deletion and resource serialization preserve a successor.

The directed PHPUnit cases cover a delayed COMMIT longer than the TTL and an expired row still present when its wrapper releases. The reusable E4 diagnostic runs the existing public ownership controls, then five lease cases at RR and RC: delayed COMMIT with exact cleanup, a delayed resource locking statement with a fresh lease start, a simulated primary-clock offset, release of an expired owner whose row is still present, and expired-predecessor takeover with successor-safe release. The diagnostic is guarded to the disposable `wp_lock_e1` Unix socket and is accepted by the existing six-row runner. Its time-offset case rewrites only diagnostic SQL to emulate a different primary clock; it does not change system time.

The valid-lease guarantee holds at the last primary-database check after COMMIT. A later PHP pause can outlast the TTL, and this library cannot fence arbitrary application writes. Renewal remains deferred and is not part of E4-01.
