The implementation moves public acquire/release to the accepted permanent-resource-row protocol on the independent primary connection. Successful acquisition confirms a committed owner and preserves the auto-increment owner ID; release uses the captured namespace and removes only its predecessor owner. The public wrapper retains held state and owner identity when release fails, so the caller can retry. Public `exists()` distinguishes failed SELECT from proven absence. The implementation uses bounded rollback/retry for a confirmed database deadlock during release and explicit uncertainty handling for INSERT/COMMIT acknowledgment loss and connection loss. These are B2 ownership changes; E4 still owns the final lease, deadline, and recovery contracts, and E5 still owns protocol switching and upgrade/rollback.

The public diagnostic exercises actual independent processes/connections and retains owners until observation. At both RR and RC in each row, two first WRITE creators exclude each other, two first READ creators coexist, ordinary READ/READ coexists, and WRITE/WRITE and READ/WRITE conflicts do not produce overlapping valid owners. Two independent readers also each acquire and release the same existing resource 25 times. Directed cases cover real acquire and release lock waits, outer caller rollback, `exists()` SELECT failure, failed release retry, uncertain INSERT and COMMIT acknowledgment, committed but unconfirmed acquisition, namespace capture after prefix change, and predecessor-safe release. This is sampled interleaving evidence, including deterministic post-query fault injection; it is not a proof for every schedule or physical packet loss.
